# SOCForge — Beginner's SOC & SIEM Terminology Glossary

> A reference guide defining core terms and concepts used daily by Security Operations Center (SOC) analysts and Detection Engineers.

---

## 1. Core Architecture & Operations

### SOC (Security Operations Center)
A centralized organizational unit responsible for monitoring, detecting, investigating, and responding to cyber threats 24/7 across an organization's network, endpoints, servers, and cloud infrastructure.

### SIEM (Security Information and Event Management)
A technology platform that aggregates log and event data from across an enterprise, normalizes it, applies correlation rules, and provides real-time alerting, searching, and dashboarding (e.g., Wazuh, OpenSearch, Splunk, Elastic, Microsoft Sentinel).

### Agent
A lightweight software service installed on a target operating system (Windows, Linux, macOS) that collects system events, log files, process activity, and file integrity data, securely transmitting them to the central SIEM Manager.

### Indexer
The backend search and analytics database engine (e.g., OpenSearch / Elasticsearch) responsible for storing, indexing, and executing high-speed searches across millions of log events.

### Dashboard
The web-based visual interface (e.g., OpenSearch Dashboards) used by analysts to view graphical summaries, drill down into search results, filter by time windows, and track key security metrics.

## 2. Telemetry, Logs & Detections

### Log
A raw, timestamped record of an event that occurred on a system or network device (e.g., a line in an Nginx access log, a Windows EventLog entry, or a firewall connection record).

### Event
A discrete occurrence or state change captured within an operating system or application (e.g., a user logging in, a process launching, or a file being modified).

### Alert
A notification generated by a SIEM rule engine when incoming log events match predefined conditions or behavioral thresholds indicative of security threats, policy violations, or anomalies.

### Decoder
A parser configuration (often XML or regex-based) that extracts structured variables (such as `srcip`, `user`, `url`, `status`, `pid`) from unstructured raw log strings so they can be evaluated by detection rules.

### Rule
A conditional logic statement evaluated against decoded event fields. In Wazuh, rules are organized into hierarchical parent-child relationships and assigned severity levels from 0 (informational/grouping) to 15 (critical compromise).

### Severity Level
A numerical or categorical score indicating the urgency and potential impact of an alert. In SOCForge:
- **Level 0–3 (Low/Informational)**: Routine system activity, baseline events.
- **Level 4–7 (Medium)**: Probing, policy violations, minor configuration anomalies.
- **Level 8–10 (High)**: Known exploit attempts, credential attacks, unauthorized privilege changes.
- **Level 11–15 (Critical)**: Confirmed remote code execution, active root compromise, multi-source correlation.

## 3. Host Telemetry & Auditing Frameworks

### Sysmon (System Monitor)
A Microsoft Sysinternals device driver and service that monitors and logs detailed Windows system activity to the Windows Event Log, including:
- **Event ID 1**: Process Creation (captures full command line, parent process lineage, and cryptographic hashes).
- **Event ID 3**: Network Connection (captures destination IP, port, and originating process).
- **Event ID 10**: ProcessAccess (detects unauthorized memory read access to `lsass.exe`).
- **Event ID 11**: FileCreate (tracks file drops in sensitive paths).

### Linux `auditd`
The native Linux kernel audit subsystem that monitors system calls (`execve`, `open`, `unlink`), capturing which user account (EUID) executed specific commands on the server.

### FIM (File Integrity Monitoring)
A defensive capability that monitors critical system binaries, configuration files, and web roots for unauthorized creation, deletion, or cryptographic checksum changes (e.g., detecting a new web shell dropped in `/var/www/html/`).

## 4. Threat Intelligence & Investigation Concepts

### IOC (Indicator of Compromise)
Forensic artifact or data point observed on a network or host that indicates an intrusion (e.g., a specific malicious IP address, malicious domain, or SHA256 file hash).

### TTP (Tactics, Techniques, and Procedures)
The behavioral patterns, methods, and tradecraft employed by adversaries to execute attacks across the cyber kill chain.

### MITRE ATT&CK Framework
A globally accessible knowledge base of adversary tactics, techniques, and sub-techniques based on real-world observations. It provides a common language for describing attacker behaviors (e.g., `T1059.001` for PowerShell execution).

### Correlation
The analytical process of linking multiple disparate log events across different log sources, hosts, or protocols over time to establish a coherent, high-confidence incident chain.

### True Positive (TP)
A SIEM alert that correctly identifies genuine malicious activity, unauthorized access, or policy violation requiring analyst intervention.

### False Positive (FP)
A SIEM alert triggered by benign, legitimate, or authorized administrative activity that superficially resembled an attack pattern.

### Incident
An unmitigated, confirmed security event or policy violation that compromises the confidentiality, integrity, or availability of an information system.

### Incident Response (IR)
The structured methodology and workflow executed by security teams to handle a security breach or cyberattack, encompassing Preparation, Detection & Analysis, Containment, Eradication, Recovery, and Post-Incident Lessons Learned.
